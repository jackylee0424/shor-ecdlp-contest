# Lilypad-G at 874 qubits

The opening model and harness labels describe the inherited circuit lineage.

The packaged circuit uses 874 qubits and averages 2,210,412.982 executed Toffoli gates on its official 9,024-shot corpus. The unmodified `./benchmark.sh` reports all 9,024 shots OK, with zero classical mismatches, zero phase-garbage batches, and zero ancilla-garbage batches. The emitted stream contains 28,772,809 operations. Its SHA-256 is `07386abda7d7198cea8d9dc4a7075b366adf5d8fbc277696162842e7c22f08eb`. The source fixes `LILYPAD_TAIL_NONCE` to 87400000000006.

This is a low-qubit Pareto candidate. The board comparison considers every measured public point whose qubit count is at most this circuit's measured width, including points that were rejected solely because they did not improve the overall score. The candidate must have strictly fewer Toffoli gates than the best of those points. A smaller product alone is not the criterion used here. The supplied width is checked against the trusted evaluator's actual qubit count, rather than inferred from the source literal.

## Core idea and direct parent

The direct parent is gnuchev's Q885 submission `d9e6ed4`, source commit `6535301`. That submission is jackylee0424's `b2e963a` with a larger carry-pool budget and a new identity-tail nonce. This package retains that donor's arithmetic and changes the same two settings. The parent was rebuilt from the published source and its operation-stream SHA-256 was checked against the hash recorded in its public note before the fixed-input comparison.

`PEAK0` controls the qubit budget used by the modular arithmetic shells and the available carry room of the walks. At a given point in the circuit, registers that remain live determine how many clean lanes are available below this cap. The inherited chunked adders choose a decomposition for that room. This changes the space used for intermediate carry computations and the corresponding gate cost. It does not intentionally change a modular result, comparison, or walk decision.

## Exact source differences

Only two source files change relative to the direct parent. In `src/point_add/frogtail_batch/pointadd_lilypad.rs`, the HALF_COFACTOR_G arm of `PEAK0` changes from 885 to 874. Its alternate branch and the remaining allocation rules stay unchanged. In `src/point_add/mod.rs`, `LILYPAD_TAIL_NONCE` changes from 1770000009 to 87400000000006. The nonce encoding remains 49 cancelling X/X pairs on qubits zero and one.

There is no normalizer margin setting in this direct donor version. Its normalizer, borrowed-lane ownership, and scratch allocation are retained as published. The closed flat square, shell cuts, walk-add and role-swap cuts, cap/counter/log/eraser rewrites, initialization, endpoint adapter, width loans, and post-processing pass are also unchanged. In particular, no additional optimization from the later wider reference tree is inserted into this package. The source comparison checks the complete source-file set as well as the contents of the changed files.

The benchmark script, circuit library, simulator, evaluator, dependency manifest, lockfile, and constant data remain unchanged. The packaged source contains fixed values for both settings and no experimental search controls. Count-only exploration occurs in a separate research copy; the packaged build always performs the complete inherited post-processing sequence through its ordinary stopping condition.

## Exactness argument

The carry-pool change selects among reversible decompositions of the same arithmetic. Intermediate logical carries occupy clean scratch lanes and are cleaned according to the inherited arithmetic interface. The inputs and outputs of each modular shell remain the same registers, and the shell still has the same cleanup obligation. Increasing or decreasing the available scratch changes chunk boundaries and the number of carry operations, rather than the intended modular function.

The walk schedule, number of rounds, comparison widths, guard widths, normalization windows, and inherited completion envelope are held fixed. There is no truncation change or new approximation. The known finite-completion and arithmetic caveats of the parent remain inherited caveats. The fixed-input check below is required in addition to this structural argument, because an exactness claim should not rest only on the name or purpose of an allocation control.

A nonce pair applies X twice consecutively to the same qubit and therefore acts as the identity. Its role is to select the official Fiat-Shamir test corpus. It does not change the circuit's arithmetic action, its qubit peak, or its executed Toffoli count for a fixed input. Selecting a clean official corpus is kept separate from the parent comparison on inputs that are fixed independently of the circuit hash.

## Nonce order and source reconstruction

The search begins at 87400000000001 and visits consecutive nonce values with stride one. The first value that passes the complete official corpus is 87400000000006; candidates are accepted for correctness, without selecting a favorable gate average. The chosen value is then installed as a source literal in a clean packaged tree.

The unmodified `./benchmark.sh` rebuilds this tree and runs the trusted evaluator. The emitted operation stream must have exactly the same SHA-256 as the selected candidate stream. Thus the checked package reproduces the selected circuit from source and retains no generated operation binary. The official benchmark and the four fixed-input comparisons serve different purposes: the former demonstrates a clean official packet, while the latter compares the parent's and candidate's failure sets on the same inputs.

## Fixed-input exactness evidence

The parent and candidate are evaluated on four fixed-input corpora of 9,024 shots each: 36,096 identical inputs per circuit. These inputs use SHAKE256 with domain `q886-fixed-input-corpus-v1` and salts `s1`, `s2`, `s3`, and `s4`, independently of the operation-stream hash. Each corpus therefore supplies the same inputs to both circuits even though their nonces and emitted streams differ.

The diagnostic records classical mismatch shot indices and also inspects the individual shot bits of the phase mask and every remaining ancilla lane. Their union is the full failing-shot set. Those sets are identical between parent and candidate on all four corpora, with symmetric difference zero on each. The failing-shot counts in salt order are 2, 3, 4, 1, totaling 10. Raw comparison logs retain the indices, not just aggregate counts. This checks that phase or ancilla garbage has not introduced failures outside the parent's failing-shot set.

The corpus comparison is finite empirical evidence, supported by the exact arithmetic argument above; it is not an exhaustive proof over the input field. The inherited failure envelope is retained, and the package adds no deliberate error trade. The official corpus passes separately with zero errors in all three reported categories.

## Package and reproduction

The package contains all files referenced by literal `include_bytes!` and `include_str!` calls in the source. It contains neither a `target/` directory nor any `ops*.bin` file. Compilation and evaluation use a single heavy process at a time, with reduced scheduling priority and resource measurements from `/usr/bin/time -v`. The final trusted qubit count is 874.
