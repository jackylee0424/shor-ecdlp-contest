## 1. What changed

`SCHED_J2` (`src/point_add/trailmix_ludicrous/schedule.rs:21`) is the per-divstep active width of the GCD registers
`u`,`v` in the jump-2 binary extended Euclid inversion. Narrowing its **tail** by 2 over the last 128 entries, with
`GAP_J2` narrowed in lockstep, and lowering `TLM_TARGET_Q` / `TLM_SQUARE_PEAK_CAP` from 1152 to 1150.

This improves **both** score axes at once, which is unusual and is the reason it is worth doing:

- **Qubits:** the walk's live register set shrinks, so the peak drops.
- **Toffoli:** every adder, comparator and cswap inside the walk is built to the scheduled width, so narrowing the
  schedule makes them all cheaper. Emitted CCX fell 1,381,252 -> 1,372,333 *before* any of the qubit accounting.

`GAP_J2` must move with `SCHED_J2`. The divstep's correctness depends only on the difference
`s = SCHED_J2[i] - cmp_window(i)`; move one without the other and the channel goes from ~8 mismatches per 9024 shots
to ~4,600. This is the single most likely way to reproduce this change and get a broken circuit.

### The trap that makes this look like it does not work

**Narrowing alone buys exactly zero qubits.** We measured this four times in a row and got peak 1153 every time,
freeing 4, 12, 24 and 48 schedule entries respectively. The reason is that the vent pool is sized
`TLM_TARGET_Q - active`, so it simply expands to absorb whatever the schedule frees. The peak never moves.

Conversely, lowering the cap alone also loses: pure cap reduction costs ~2,590 emitted CCX per qubit against a
break-even of ~1,188 CCX/qubit at this operating point, i.e. it loses about 2:1.

**Only the combination wins,** because the qubit comes from the schedule and the Toffoli reduction comes from the
narrower arithmetic, and the cap is what converts the first into an actual change in the scored maximum.

### The measured frontier

All with `SUB4_APPLY_STRIP=0` so the numbers are pure, i.e. not confounded by the dead-gate strip:

| narrowing | cap | peak | emitted CCX | lambda classical |
|---|---|---|---|---|
| none (previous head) | 1152 | 1153 | 1,381,252 | 6.08 |
| last 160 by 1 | 1151 | 1152 | 1,375,689 | 9.67 |
| last 96 by 2 | 1150 | 1151 | 1,375,272 | 9.58 |
| **last 128 by 2 (this)** | **1150** | **1151** | **1,372,333** | **13.88 +- 0.81** |
| last 160 by 2 | 1150 | 1151 | 1,370,237 | 14.92 |
| last 258 by 1 | 1151 | 1152 | 1,373,437 | 1386 -- destroyed |

The early `SCHED_J2` entries are a genuinely tight magnitude bound on the Bezout quantities; all the slack is in the
tail. Depth 2 works, depth 1 across the whole vector does not.

## 2. The re-mined census, and why a geometry change forces one

`src/point_add/deep_strip_keys.rs` is a table of gates proven dead or control-redundant by exhaustive census over
random on-curve inputs. Its keys are `(kind, q_control2, q_control1, q_target, c_condition, k-th occurrence ordinal)`.

**Changing any width or schedule shifts those ordinals.** Running the previous table against this geometry gave
`6,241 stale keys skipped` and 8,720/9,024 mismatches -- not a subtle degradation, a broken circuit. We burned a
3,264-vCPU grind discovering this the expensive way, because the build reported a good peak and a good Toffoli count
and we did not run `eval_circuit` before scaling out. **A peak/Toffoli probe is not a validation gate.**

Re-mined from scratch for this geometry: **1,000,005,632 shots**, 8 x 1.25e8 disjoint seeds, 190 threads, ~16 min on
192 cores. Result: **9,041 dead gates + 2,045 CCX->CX/CZ downgrades = 11,086 keys**, and
`0 stale keys skipped` on the shipped build.

Convergence, so the next person knows where the returns stop:

| shots | dead | downgraded |
|---|---|---|
| 1.25e8 | 9,752 | 2,191 |
| 2.5e8 | 9,486 | 2,133 |
| 5e8 | 9,239 | 2,094 |
| 7.5e8 | 9,115 | 2,067 |
| 1e9 | 9,041 | 2,045 |

Still falling slowly at 1e9; residual false-dead mass beyond 1e9 is under 1e-3 failures/9024. A 1e8 census
over-counts dead gates by ~5% and will ship you a broken circuit.

Emitted arithmetic is exact: 1,372,333 - 11,086 = **1,361,247** Toffoli-family (CCX 1,355,977 + CCZ 5,270).
Executed/emitted ratio 0.956340 -> **1,301,815 executed**.

## 3. Validation

- **`eval_circuit`, zero env vars, reproduced on two independent machines** (the 192-core build host and a separate
  workstation, both from a clean `cargo build`): 1151 qubits, `0 classical / 0 phase / 0 ancilla`, all 9024 shots
  OK, `avg executed Toffoli 1301797.555`, `0 stale keys skipped`.
- **n=16 lambda table**, every point a real `build_circuit` + `eval_circuit` on random Fiat-Shamir seeds, all 16
  logging `0 stale keys skipped` and `qubits=1151`: classical 13.88 +- 0.81, phase 9.88 +- 0.73, ancilla 0/16.
- **Score is nonce-stable:** across those 16, executed Toffoli ranged 1,301,793 .. 1,301,824 (sd 7.4), a 36k spread
  on 1.5e9. The score does not depend on which clean seed you ship.
- **The fast screen was proven exact against the trusted harness on 64 independent comparisons** (16 nonces x
  {classical, phase, ancilla, avgT}), identical printed values to three decimals, not "agrees within noise". This
  matters because the nonce search is done by the screen, not the harness, and a screen with false negatives grinds
  forever while a screen with false positives wastes verification. Useful trick discovered here: `eval_circuit`
  writes `avg_tof`/`avg_cliff` into `results.tsv` **even on FAIL rows**, so exact per-nonce ground truth is available
  without needing a clean nonce first.
- **P(clean) measured directly over 20,000 nonces**, not inferred from lambda: mean 9.20 batches to first failure ->
  q = 0.891258 -> P(0/0 over 141 batches) = 8.922e-8, i.e. **1.12e7 nonces per expected clean seed**.

### On the intrinsic error rate, which we think is under-appreciated here

The shipped circuit is correct but not *unconditionally* correct: it is a measurement-based (Gidney-style) uncompute
whose phase corrections cancel only for a Fiat-Shamir seed that happens to work. At lambda_total ~ 23.3 the
probability a *fresh* random seed is clean is about 7e-11. Every submission on this leaderboard, including every one
of ours, ships a seed found by brute force.

This means a submission's headline number is a property of (circuit, seed), and a small enough edit can be carried
by a lucky seed rather than by being better. We think the right objective is **minimise Toffoli subject to lambda
staying small enough to grind**, and we deliberately chose this variant at lambda 13.88 over a cheaper-to-grind
alternative at lambda 9.58 because the fleet makes 1.1e7 candidates a 40-minute problem.

## 4. First-principles analysis of the qubit floor

We were asked whether ~800 qubits is reachable. We measured the peak's ownership rather than guessing. Owner census
at the binding op (3,452,906 of 9,154,238, phase `tlm_apply_inverse_fold`):

| qubits | site | role |
|---|---|---|
| 603 | `gcd.rs:1353` | divstep transcript ("dialog tape") |
| 256 | `mod.rs:459` | `y`, the apply-target register |
| 256 | `gcd.rs:1902` | `tmp`, scratch the divisor is swapped into |
| ~37 | various | adder carries, fold state, scalars |

**The tape is closed.** Its information floor is 258 divsteps x log2(5) = **599 bits**, and exact backward
enumeration of reachable k-suffixes gives exactly (5^k+1)/2 states, so the codec at 603 is within 4 qubits of
optimal. Do not spend time there.

**The 512-qubit apply pair is irreducible, and we tested this rather than assuming it.** The two 256-blocks are
`(x_reg, y_reg)`, the vector the accumulated Bezout matrix acts on. It starts at `(0, y0)`, so all 256 qubits of
`x_reg` are provably |0> at entry -- which looked like 256 free qubits. It is not: `apply_step_reverse` opens with an
unconditional full-width `cswap` over all 256 bits whose control is quantum data, so **every one of the 256 is first
touched during divstep 0**, at op 23,444 of 3,448,854, where the live count is 1,027 -- 125 qubits *below* the peak,
which lands at divstep 259. Measured provably-zero population at the peak op: **0 of 256**. The mirror direction has
the identical shape. Both components are genuine full 256-bit residues (`a_i*y0`, `b_i*y0 mod p`) for the entire
walk. We built the loaning machinery anyway (`TLM_LOAN_APPLY_ZEROS`, defaulted off) to be sure the negative was
structural and not an implementation failure: it runs clean, and buys **zero** qubits at every cap from 1151 to 1120.

**The ABI floor is 512.** The harness mandates `target_x` and `target_y` as 256-qubit registers and scores
`max(qubit_id)+1` (`src/circuit.rs:348-363`), so indices 0..511 are touched unconditionally.

So the governing invariant is `peak ~ 512 + max_i [ tape(i) + state(i) ] + ancilla`, and since the tape grows at
2.33 bits/divstep while `u`,`v` shrink at 2 bits/divstep, the workspace curve is `512 + 0.33i` -- almost flat,
maximised at the end of the forward walk.

We then **measured** the floor rather than estimating it, and the measurement is sharper than the argument:

- **Sweeping the cap `TLM_TARGET_Q` = `TLM_SQUARE_PEAK_CAP` from 1151 down to 800**, peak qubits go
  1152, 1151, 1150, 1149, 1148, **1147 -- and then stick at 1147 for every cap at or below 1146, including 800.**
  At cap 800 emitted CCX is 1,714,304 (+25%) and the peak has not moved a single qubit. The "lower the cap too"
  lever has a hard ceiling of exactly 5 qubits; past that you pay Toffoli for nothing.
- Composition of that 1147: 585 tape + 256 `y` + 256 `tmp` + 14 `u` + 14 `v` + 18 fold scratch + 4 flags.
  Against an information floor of 599 + 512 + 28 + 4 = **1143**. The circuit is within 4 qubits of its algorithmic
  floor.
- **The exchange rate worsens as you push**, in executed Toffoli per qubit (strip=0): 1152->1151 costs 1,596/q,
  ->1149 costs 1,748/q, ->1147 costs 1,935/q, against a break-even of T/Q = 1,141/q. Peak 1147 scores
  1147 x 1,324,056 = 1,518,692,232 versus 1152 x 1,315,094 = 1,514,988,288 at the same strip setting -- the cap
  lever is a **0.24% loss**, not a win. The qubit we took came from the *schedule*, not the cap.
- **The peak is doubly binding.** A timeline census shows max_active = 1152 in three phases across both walk
  directions (`tlm_apply_inverse_fold`, `tlm_apply_forward_fold`, `tlm_apply_inverse_mod_sub_fold`), plus an 1151
  shelf in twelve more. Any saving that applies to only one direction is worth exactly zero.

**So the achievable floor at this geometry is 1147, the algorithmic floor is 1143, and we are at 1151.**

Reaching 800 means workspace <= 288 while the transcript alone needs 599. That requires pebbling -- recomputing
transcript segments instead of storing them. We priced it. The score is a product, so at 800 qubits the Toffoli
budget is 1,502,937,216/800 = 1,872,000, i.e. +44%, which is more generous than a linear break-even suggests. It is
still not enough:

| blocks B | resident workspace | peak | extra forward walks | extra CCX | verdict |
|---|---|---|---|---|---|
| 1 (today) | 599 | 1147 measured | 0 | 0 | -- |
| 3 | 456 | ~988 | 1.5 | ~495k | at budget |
| 4 | 406 | ~938 | 2.0 | ~660k | just over |
| 19 | 288 | **~800** | ~9.5 | **~3.1M** | ~4x worse score |

**Iso-score floor is roughly 950-1000 qubits; 800 is below it, and the cap sweep independently shows the peak
physically refuses to go below 1147 no matter what you pay.** The 824-838 qubit attempts in this leaderboard's
history, all at 150-500x the Toffoli, are the empirical confirmation.

**The one thing that would change this answer.** The transcript is an injective function of the 256-bit input, so
its true entropy is 256 bits, not 599 -- there are 343 bits of pure redundancy in the tape, and
512 + 256 + ~20 = **788**, which is the target. The obstruction is constructive, not information-theoretic: the only
bijection anyone knows is "the input itself", and recovering symbol i from it costs O(i) walk steps. A **streaming,
cheaply-invertible code from divstep transcripts to 256 bits** would hit 800 directly. We do not know how to build
one and we flag it as the open problem rather than an engineering task.

## 5. Honest gaps

- **Lambda went up**, 6.08 -> 13.88. We bought a qubit and 9k emitted CCX with a 24x harder nonce search. That is a
  fair trade only if you have a fleet; on one box it is 20 hours.
- The n=16 lambda point estimate (13.88 +- 0.81) sits above the 1,000,448-sample pre-strip estimate (12.73 +- 0.34).
  They agree within 1 sigma combined and we report both rather than the flattering one.
- We tested one adjacent lever and it was a wash, recorded so nobody repeats it: `TLM_FFG_RELEASE_CY0_DURING_SUFFIX`
  with its call list widened to all indices costs +2,148 ops for zero qubits, and disabling it entirely saves 240 ops
  for zero qubits -- 0.003% of the stream, inside the noise of needing a fresh nonce.
- We have **not** re-swept the qubit dial from scratch since discovering that the previous "1152 is a structural
  floor" verdict was an artifact of a corrupted measurement. That verdict was wrong twice now (1153 -> 1152 -> 1151).
  Anyone with compute should re-run the exchange curve properly rather than trusting published floors, including
  ours.

tool is a single dependency-free file; the mined table is only reproducible together with the tool that mined it, so
